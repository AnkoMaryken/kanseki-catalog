v9.3 · 桌面版 0.12.0 2026-10-02 新增 修复 调整
  • 修复「deepseek 返回了空内容」：原因是模型名与 token 预算两处都不对。
    · DeepSeek 现行模型是 deepseek-flash / deepseek-v4-pro， 旧名 deepseek-chat / deepseek-reasoner 已不在官方价格表内 —— 本软件此前写死了旧名。 现在「API 管理」里的模型列表直接向接口拉取（可点「刷新列表」），不再写死。
    · 思考模式下思维链与正文共享同一份 token 预算，此前单条复检只给 400 tokens， 推理模型的预算全被思维链吃光、正文自然为空。现在默认给 8000，并可在设置里调整； 万一正文仍为空，会自动回落到思维链内容并明确标注，而不是只报一句「空内容」。
  • AI 复检会联网查证了：复检时程序先自己上网检索，把查到的网页标题/摘要/链接 作为「网络查证资料」交给模型，要求它据此与现有分类交叉核对；结果区会显示 「已联网查证：N 条网络资料」及来源链接。

  • 可直接复检搜索框里的书：表格里选中某行 → 复检该条；未选中时改为复检搜索框内容， 因此本表没有收录的书也能查（提示词会带上本表中书名相近的条目供核对， 并说明本表未收录）。
  • 输出先给一致性结论：回答第一行固定为「【一致性】一致 / 可能不一致 / 不一致」， 与当前《中国古籍总目》分类核对；不一致或可能不一致一律标红并给出修改建议， 另附「反馈错误结果」面板（邮件 / 复制报告）。
  • 导出改为右下角通知栏：导出 CSV / Markdown 后，主界面右下角弹出横条通知， 显示文件名与完整保存路径，并提供「打开文件」「打开所在文件夹」按钮 —— 不再是默默下到某个不知道的文件夹里。桌面版会明确保存到系统「下载」目录（同名自动加序号，不覆盖）。

v8.9 · 桌面版 0.8.2 2026-09-29 新增 修复
  • 桌面版：修复「最大化按钮有两个图标叠在一起」（本次重点）。标题栏右侧最大化按钮内部本就备有两个图标——「最大化」方块与「还原」双框，按窗口状态只显示其中一个，但两者同时显示并重叠了。原因是样式表里一条针对按钮内图标的显示规则（display:block）优先级高于浏览器对 hidden 属性自带的隐藏规则，于是「隐藏」指令被静默覆盖。现补回一条更高优先级的兜底规则，实测同时可见的图标由 2 个变为 1 个，且点击最大化后正确切换为「还原」图标。
  • 桌面版：「窗口」按钮旁新增一键简繁切换（按反馈新增）。标题栏左上角「窗口」按钮右侧加入一个方形按钮，点击即在简体／繁体之间一键对调；按钮上显示的是将要切换到的字形（当前为繁体时显示「简」），鼠标悬停有文字说明，切换后右下角会弹出提示。
    该按钮与页面内原有的简繁下拉读写同一份设置，因此两处入口始终一致——从任一处切换，另一处会同步跟随。实测点击后内嵌页面的表头文字确实由繁体变为简体、再点一次复原。
  • 全站：简繁字形选择现在会被记住（本次重点）。此前每次打开都是繁体，切到简体后一刷新就回到繁体。现改为记住上次选择，下次打开（含桌面版与网页版）保持同一字形；清除浏览器数据后恢复繁体默认值。
  • 桌面版：登录后再点「账号」直接进个人中心（按反馈修正）。侧栏「账号」项此前固定指向登录页，于是登录完成后点它又回到登录页，查看资料必须再绕一次。现在该项的目标随登录状态自动变化：未登录进登录页，已登录直接进个人中心，悬停提示也同步变化；退出登录后自动回落到登录页，并会离开个人中心（该页需登录才能查看）。
  • 桌面版：登录成功自动进入个人中心。登录页在窗口内是独立页面，登录成功后的跳转只发生在页面内部，窗口导航不会跟着变，造成「已经登录上了，界面还停在登录页」。现在登录成功后会自动切到个人中心并提示「登录成功」；同时侧栏头像与昵称立即刷新。
  • 桌面版：修复「窗口最大化等操作点了没反应」（深层成因）。此前虽已修正窗口指令的名称写法，但实测仍会间歇性失灵——点「最大化」后窗口要么纹丝不动，要么图标先变、随即又变回去。经逐条追踪指令收发与界面变化过程查明真正原因：点击其实是生效的，问题出在随后的状态回读上——窗口放大过程中会连续触发尺寸变化事件，而该事件会在放大动画尚未结束时去问内核要真实状态，此刻内核仍返回「未最大化」的旧值，于是刚点出来的正确图标被这个旧值覆盖了回去。
    实测记录（每 60 毫秒采样一次）：点击后 +121 毫秒图标已正确变为「还原」，但 +195 毫秒又被改回「最大化」，而窗口尺寸已是放大后的数值——即“窗口放大了，图标却说自己没放大”。
    现改为三重保障：
    ① 改用可重试的指令——「最大化」不再使用「翻转」式指令（翻转指令一旦重试就会翻回去），改用目标明确的「最大化／取消最大化」式指令，没到位就再发一次，重复发送无副作用；
    ② 状态保护期——程序自己改动窗口大小后的一段时间内，尺寸变化事件不采信回读结果，改由操作流程独占状态写入，待动画彻底结束后再做一次权威校准；
    ③ 二次确认——保护期之外的任何回读，都要连续两次读数一致才允许改写界面，单次读到旧值不足以推翻已经正确的显示。
    「全屏」「置顶」「按尺寸调整」同样改为「操作后回读确认」，确认到位才算成功，三轮仍未生效则明确提示「请再试一次」，不再出现「点了没反应」也毫无反馈的情况。
  • 桌面版：修复「点简繁切换后下拉菜单不收」（排查中一并发现）。页面右上的登录下拉里带有「简／繁」字形切换按钮；切换后菜单本应自动收起，但当所选字形与当前字形相同时（例如刷新后按习惯再点一下确认），程序会直接跳过后续流程，菜单停在展开状态悬在页面上，遮挡下方按钮——实测会挡住「导出」按钮导致无法点击。现调整为：只要点了字形按钮就一定收起菜单，与字形是否真的发生变化无关。
  • 桌面版：修复「最大化后图标偶尔不跟着变」（排查中一并发现）。点击最大化后，图标有概率仍停在「最大化」上，看起来同样像「点了没反应」，而窗口其实已经放大。原因是两处回读逻辑互相打架：窗口放大过程中会连续触发尺寸变化事件，该事件与点击后的状态回读都会去问内核要真实状态；在放大动画尚未结束时，内核仍返回「未最大化」的旧值，于是刚点出来的正确图标又被改了回去。现改为点击处理独占状态写入，动画期间屏蔽另一侧的回读。另修正了「按尺寸调整」的判断——该操作必然退出最大化，原先按「翻转」推断会得出相反的结论。
  • 桌面版：修复「启动后前几秒点标题栏没反应」（排查中一并发现，本次重点补漏）。程序刚打开的头几秒里，点最小化／最大化／关闭及简繁按钮全都毫无反应，等一会儿又恢复正常。实测页面时间线查明：这些按钮在页面载入约 0.4 秒时就已经画好、肉眼可见，但处理点击的程序（外壳脚本）要等到约 3 秒才被执行——中间这段两秒多的「看得见却点不动」的空窗，主因是内嵌的查询页要一次性载入数张巨大的对照数据表，占满了主线程。
    现改为两个阶段衔接：解析页面时先用一段轻量脚本把这几枚按钮的点击接住暂存，待外壳脚本就绪后立即补发一次，用户那一下点击不会丢（连点多次只按一次算）。实测在页面时间 0.11 秒处点击最大化，窗口最终正确地放大到 1440×912、图标切为「还原」，与此前「点了没反应」的表现彻底告别。
  • 桌面版：修复「最大化图标偶尔闪一下才稳定」（排查中一并发现）。启动阶段的状态回读与用户点击若同时发生，回读会在放大动画期间读到「未最大化」的旧值并把图标写回错的，随后才被保护期结束后的权威校准纠正——视觉上就是图标先跳错再跳回。现已让启动回读遵循与点击相同的保护规则：动画期间不采信回读，把状态判断让给正在执行的点击流程。
  • 桌面版：新增「可直接分享给他人」的发布包（本次新增）。此前只有开发用的编译产物，无法直接发给别人使用。现提供两种形式，一份压缩包即可完整分享：
